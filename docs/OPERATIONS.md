# Operations

## Daily checks

- `GET /health/live` — liveness
- `GET /health/ready` — database connectivity
- Error log `storage/logs/laravel.log` for `Fetch error`, `PRIVATE_IP`, `TOO_MANY_REDIRECTS`
- Rate-limited `429` responses on `/api/v1/serp-preview/fetch`

## Cache

Production cache uses Redis by default. To clear:

```sh
php artisan cache:clear
```

The `serp-fetch` cache key prefix is `serp-fetch:`. TTL is 5 minutes. To inspect:

```sh
php artisan tinker
> Cache::get('serp-fetch:' . md5('https://example.com/'));
```

## Sessions

Sessions are stored in the configured session driver (`database` or `redis`). Restarting the app server does not invalidate sessions.

## Logs

| Log path | Purpose |
|---|---|
| `storage/logs/laravel.log` | Application, fetch, and security warnings |
| `storage/logs/scheduler.log` | Scheduler output (if any) |

Configure a central log aggregator in production to alert on:

- Repeated `PRIVATE_IP` attempts
- Repeated `AMBIGUOUS_HOST` attempts
- Repeated `TOO_MANY_REDIRECTS` attempts

## Rate-limit monitoring

The `serp-fetch` limit is configured in `app/Providers/AppServiceProvider.php`:

```php
RateLimiter::for('serp-fetch', fn (Request $request) => Limit::perMinute(30)->by($request->ip()));
```

If users report `429 Too Many Requests`, the limit is working as intended. Consider raising it only after monitoring real usage.

## Storage and disk

- `public/build/` is generated by Vite. Re-create with `npm run build`.
- `storage/framework/views/` holds compiled Blade views. Re-create with `php artisan view:cache`.
- `storage/logs/` can grow on busy sites. Set up log rotation.

| Update dependencies | Monthly | `composer update` and `npm update` |
| Rotate logs | Weekly | `logrotate` or similar |
